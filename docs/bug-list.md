## BUG-001 当前对话框中的历史信息在追问后丢失

- **状态**：已修复。回答页已从单条回答详情改为当前会话消息流；主提问和连续追问都会追加用户问题与助手回答，历史会话回放也会按保存的 `messages` 重建完整问答流。
- **现象**：用户在 AI 回答页继续追问后，当前对话框里上一轮问答信息会被新一轮内容覆盖或不再可见。
- **期望**：追问应保留当前会话内的历史问答，让用户能连续查看上下文，而不是只看到最新一轮输出。
- **初步判断**：前端目前用单一 `answer-text` / `answer-question` 承载当前回答，流式追问时会重置展示区域；虽然请求侧 `state.messages` 仍用于发送上下文，但 UI 没有维护可渲染的消息列表。
- **修复说明**：将回答页从“单条回答详情”改为“当前会话消息流”，每轮 user/assistant 消息追加到列表；引用、事件时间线和后续操作仍绑定到最新一轮 assistant 消息。
- **验收标准**：连续追问 3 轮后，页面仍能看到完整 3 轮用户问题与模型回答；刷新前的同页会话不丢失当前内存状态；追问请求仍带上完整上下文。

## BUG-002 同浏览器切换账号后残留上一账号的提问草稿

- **状态**：已修复。
- **现象**：运营账号退出后再登录管理员账号，历史列表已经隔离，但首页提问框仍保留运营账号刚刚输入或发送的问题。
- **影响**：造成跨账号瞬态数据泄漏；管理员密钥列表等已渲染数据也可能继续留在隐藏 DOM 中。
- **修复说明**：新增统一的账号状态清理，在退出或会话失效时中止流式请求并清空消息、历史、草稿、回答、密钥列表及相关 DOM，再加载新账号授权数据。
- **验收标准**：账号 A 写入专属草稿并退出，账号 B 登录后只能看到默认问题或自己的数据；控制台无错误；管理员数据不会残留在非管理员页面 DOM 中。
