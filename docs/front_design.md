# Curx 前端设计路线演进

## 1. 当前原型判断

当前 KIMI-K3 原型已经能表达 Curx 的核心产品路径：知识空间首页、上传解析、AI 回答、引用溯源、原文预览和管理设置串成了一条完整链路。它适合用于早期沟通产品范围，也能帮助后端确认需要暴露哪些页面状态和 API 合同。

但它还不是最终工作台形态。当前视觉更接近通用 AI SaaS demo：蓝紫渐变、圆角卡片、柔和阴影、符号图标和流程 tabs 较多，第一印象偏“漂亮原型”，而不是“可信、可审计、可长期使用的内部知识工具”。

第一阶段前端目标不是继续堆功能，而是把产品气质收敛到一句话：

> Curx 是一个有证据、有权限、有运行轨迹的内部知识问答工作台。

## 2. 设计原则

### 2.1 工具感优先于展示感

Curx 面向内部知识运营和研发/售后问答，不应做成营销页或通用聊天入口。界面应当克制、稳定、可扫描，优先服务重复使用、快速定位、证据核查和错误排查。

具体要求：

- 减少大面积渐变、强阴影和装饰性圆角。
- 保留一个主强调色，用于主要操作、当前状态和关键引用。
- 卡片只用于真实信息单元，例如文档、引用、任务、空间；不要用卡片堆出页面结构。
- 页面密度可以更高，但层级必须清楚。

### 2.2 证据链是第一视觉中心

Curx 与普通 AI Chat 的区别不是“能回答”，而是“回答能被追溯”。因此回答页和原文页应当共同成为最重要的体验。

具体要求：

- 回答正文中的关键结论必须能直接绑定 citation。
- 右侧引用栏展示来源文档、页码/章节、摘录、相关度和权限状态。
- 点击引用后进入原文预览，并自动定位到对应段落或页内高亮。
- 证据不足时，界面明确展示“未找到足够依据”，而不是生成模糊回答。

### 2.3 导航服务任务，而不是展示流程

当前同时存在顶部搜索、左侧导航和流程 tabs，适合评审原型，但真实产品会显得重复。后续应减少导航层级，把用户注意力放回当前任务。

推荐形态：

- 左侧导航负责模块切换：知识空间、文档、问答、任务、设置。
- 顶部区域负责全局搜索、当前空间、上传入口和用户状态。
- 流程 tabs 仅保留在演示模式或设计文档中，不作为正式产品主导航。
- 页面内部使用面包屑和状态标题表达当前位置。

## 3. 页面演进路线

### 3.1 知识空间首页

当前首页偏普通聊天入口，“今天想查什么？”能传达使用方式，但没有充分展示知识库上下文。

下一版应强化：

- 当前知识空间名称、权限范围和索引健康状态。
- 已索引文档数量、最近更新时间、失败任务数量。
- 最近被引用的来源和最近问题。
- 明确的“在当前空间内提问”输入框。

首页的首屏应让用户确认三件事：我在哪个知识空间里、这个空间是否可信、我可以基于哪些资料提问。

### 3.2 上传解析页

当前上传页已经有拖拽、进度条和解析完成反馈，但状态偏静态。

下一版应补充真实入库生命周期：

- 文件队列：等待、解析中、索引中、完成、失败。
- 阶段状态：提取文本、结构化 Markdown、切片、向量化、全文索引。
- 解析结果：页数、章节数、表格数、图片数、切片数量。
- 失败原因：文件损坏、权限不足、模型失败、对象存储失败。
- 操作入口：重试、取消、查看原文、查看切片。

这个页面是运营人员建立信任的关键，不能只做成上传控件。

### 3.3 AI 回答页

回答页是 Curx 的主体验。后续应从“回答 + 引用列表”升级为“回答、运行过程、证据三栏协同”。

建议结构：

- 主栏：问题、回答、关键结论、后续追问。
- 过程栏或时间线：理解问题、检索资料、提取证据、生成回答。
- 证据栏：引用来源、页码、摘录、相关度、打开原文。

交互要求：

- 回答中的 citation 可点击。
- 鼠标悬停 citation 时，右侧引用同步高亮。
- 点击引用进入原文预览时保留返回回答的上下文。
- 低可信回答要明显降级展示，避免和高可信回答视觉相同。

### 3.4 原文预览页

当前原文预览能展示一段高亮文本，但还没有形成强溯源体验。

下一版应支持：

- 页码/章节定位。
- 引用段落高亮。
- 左右相邻上下文查看。
- 文档元信息：版本、上传人、更新时间、权限范围。
- 返回回答时保留选中的 citation。

原文预览不是独立阅读器，而是回答可信度核查工具。

### 3.5 管理设置页

设置页当前覆盖权限、访问 KEY、索引策略和安全状态，方向正确。

后续应按风险拆分：

- 访问与成员：谁能进入空间。
- 激活密钥：创建、复制一次、撤销、过期时间。
- 索引策略：自动更新、重建索引、标签规则。
- 审计日志：登录失败、密钥绑定、文档读取、回答生成。

高风险操作需要明确二次确认和结果反馈，不能只靠一个“保存设置”。

## 4. 视觉系统改进

### 4.1 色彩

当前蓝紫渐变较多，容易落入通用 AI 产品模板。建议改成更克制的工具型色彩系统：

- 主色：用于当前空间、主操作、citation 高亮。
- 中性色：用于页面背景、面板、分割线和正文。
- 状态色：成功、警告、失败、处理中。
- 禁止把渐变作为常规按钮和页面背景的默认表达。

### 4.2 字体与层级

中文界面可以继续使用系统中文字体，但层级需要更像工作台：

- 页面标题减少夸张字号。
- 数据、状态、来源标题更清晰。
- 辅助文本保证对比度，不低于可读标准。
- 按钮文字避免过多情绪化表达，使用任务语言。

### 4.3 图标与控件

当前符号图标能快速搭原型，但长期维护会不统一。

建议：

- 后续统一使用图标库，例如 lucide。
- 工具按钮用熟悉图标：上传、搜索、设置、复制、打开原文、返回。
- 不使用 emoji 或装饰符号作为核心 UI 图标。
- 重要按钮保持 44px 左右的可点击高度。

## 5. 响应式策略

当前移动端会把侧栏、流程 tabs、右侧栏全部堆叠，真实使用时路径会过长。

下一版移动端策略：

- 左侧导航折叠为抽屉或底部少量核心入口。
- 隐藏流程 tabs。
- 首页优先展示当前空间、搜索/提问框和最近引用。
- 回答页优先展示答案，引用栏变成可展开底部面板。
- 上传任务用列表而不是大面积拖拽区域。

移动端目标不是完整复刻桌面，而是保证提问、看答案、查引用三件事顺畅。

## 6. 优先级路线图

### P0：收敛原型为可信工作台

- 移除或弱化流程 tabs，减少导航重复。
- 降低蓝紫渐变和强阴影使用频率。
- 调整首页，让知识空间状态成为首屏信息。
- 回答页强化 citation 与右侧来源的对应关系。

### P1：补齐核心信任链路

- 回答正文支持可点击 citation。
- 原文预览支持引用定位和高亮。
- 上传解析展示真实阶段和失败状态。
- 回答过程使用后端公开事件合同：`answer.started`、`query.understood`、`retrieval.started`、`evidence.ready`、`answer.generating`、`answer.completed`、`answer.failed`。

### P2：面向运营与权限管理

- 增加索引任务列表、失败任务和重试入口。
- 完善激活密钥、成员、权限范围和审计日志页面。
- 展示知识空间健康度和引用质量指标。
- 增加低可信、证据不足、无权限来源等异常态。

### P3：体验 polish

- 统一图标系统。
- 建立正式色彩变量和状态 token。
- 优化移动端布局。
- 增加细节动效，但仅用于状态变化、引用定位和面板展开。

## 7. 验收标准

前端进入可试用状态前，应满足：

- 用户首屏能明确知道当前知识空间、资料状态和可执行动作。
- 每条回答的关键结论都能定位到具体引用。
- 引用可以打开原文，并看到对应上下文。
- 上传解析过程有可解释状态，失败时有原因和下一步操作。
- 权限、密钥、索引策略等高风险页面不与普通展示页面混在一起。
- 桌面端不依赖装饰性渐变和阴影来建立层级。
- 移动端能完成提问、查看回答、核查引用三条核心路径。
