# Curx 产品设计任务书

> 本文件迁移并吸收了 AidBot 的 `mvp-architecture.md` 与 `task_plan.md`，但不复制
> AidBot 的实现状态。Curx 的产品边界以 `docs/system-design.md` 为准，界面约束以
> `docs/front_design.md` 为准，本文件负责把两者转换成可持续执行、可验收的开发任务。

## 1. 使用方式

本文件是 Curx 后续开发的主任务书。

- 每次开始开发前，先检查本文件、`docs/bug-list.md`、当前代码和
  `graphify query "<本次任务>"`。
- 每次只选择一个可以独立验收的最小闭环，不跨阶段堆叠半成品。
- 完成代码后，补齐相关测试、浏览器回归和文档证据，再更新阶段状态。
- 修改 API 合同、产品边界或视觉约束时，同步更新 `docs/system-design.md` 或
  `docs/front_design.md`。
- 修改代码后执行 `graphify update .`，保持项目知识图谱与代码同步。

## 2. 产品目标

Curx 是面向公司内部研发、售后、客服和知识运营人员的“有证据支撑的知识问答工作台”。
第一版要完成以下最小闭环：

```text
用户获得访问权限
  -> 在授权知识空间内提问
  -> 系统检索受控资料
  -> 生成带引用的回答
  -> 用户核查原文并反馈质量
  -> 运营人员追溯检索、引用和处理结果
```

Curx 的核心价值不是单纯生成答案，而是让答案具备以下四个特征：

1. **有依据：** 关键结论能定位到具体文档版本和分块。
2. **有权限：** 未授权内容不能进入检索结果、模型上下文或引用列表。
3. **有轨迹：** 每次回答的公开阶段、检索候选、最终证据和耗时可追溯。
4. **可运营：** 失败任务、低分回答、过期知识和访问异常有明确处理入口。

## 3. 用户与职责

| 角色 | 核心任务 | MVP 权限 |
| --- | --- | --- |
| 普通用户 | 提问、追问、查看引用、打开原文、提交反馈 | 只访问被授权的知识空间和历史会话 |
| 知识运营人员 | 上传资料、查看入库状态、重试失败任务、处理反馈 | 管理指定知识空间及其来源 |
| 系统管理员 | 创建激活密钥、管理授权、撤销访问、查看审计记录 | 管理租户级配置和安全操作 |

第一版不提供外部客户门户，也不把 Provider API Key 交给普通用户。Curx 激活密钥只用于
建立平台访问权限，模型 Provider 凭据只保存在服务端。

## 4. MVP 范围

### 4.1 第一版必须完成

- 用户通过“用户名 + Curx API Key”首次绑定并换取安全浏览器会话。
- 管理员可以创建、一次性查看、复制、设置有效期和撤销激活密钥。
- 用户可以选择被授权的知识空间并进行多轮问答。
- Markdown、HTML、PDF、DOCX 和手工 FAQ 可以异步入库。
- 文档完成标准化、层级切片、全文索引和向量索引。
- 回答使用带权限过滤的混合检索，并保存检索运行记录。
- 每条有依据的回答包含可持久化引用；证据不足时明确拒答或建议转人工。
- 引用可以打开原文并定位到对应页码、章节或段落。
- 用户可以对回答评分并填写原因。
- 运营人员可以查看入库失败、低分反馈、检索轨迹和审计日志。
- 桌面端和移动端都能完成“提问 -> 查看回答 -> 核查引用”主路径。

### 4.2 第一版明确不做

- 多租户 SaaS 计费和外部客户自助注册。
- 飞书实时权限同步和工单系统双向同步。
- 面向普通用户的多 Provider 密钥管理。
- 播客、音频生成、视频转写和通用多模态索引。
- 能自主写入外部系统的 Agent。
- 多 Agent 编排可视化和 Prompt A/B 平台。
- 跨知识空间复用同一来源。
- 没有评测证据支撑的重排序器或复杂 LangGraph 工作流。

## 8. 稳定产品合同

### 8.1 回答请求

前端通过 `POST /api/chat/stream` 发送完整 `messages` 上下文和可选
`knowledge_space_id`。追问不能只发送最后一个问题。

### 8.2 公开流式事件

正式回答流程对前端公开以下事件：

```text
answer.started
query.understood
retrieval.started
evidence.ready
answer.generating
answer.delta
answer.completed
answer.failed
```

- `answer.delta` 只追加正文。
- `answer.completed` 返回最终答案、公开阶段、引用和下一步操作。
- 事件只包含可展示摘要、耗时、候选/证据数量和安全来源 ID。
- 原始思维过程、系统提示词、密钥和无权限候选不得进入事件或普通日志。

### 8.3 工作流边界

```text
Chat API
  -> AnswerWorkflow
      -> LinearRagWorkflow
      -> LangGraphRagWorkflow
  -> AnswerResult
  -> SSE / REST Response
```

LangChain、LangGraph、向量库和具体模型 Provider 都属于内部实现。前端和 API 领域模型
不能依赖其节点名称、状态结构或 SDK 参数。

## 9. 前端产品任务

### 9.1 一级导航

左侧一级导航只展示：

- AI 问一问
- 知识空间
- 管理设置

上传解析属于知识空间子页面；原文预览只在用户打开文档或引用时出现。

### 9.2 AI 问一问

- 首页使用长提问框，桌面端右侧默认最多展示 5 条历史会话。
- 主问题和继续追问支持 Enter 发送、Shift+Enter 换行。
- 等待首段模型内容时展示“AI 正在思考中”，收到首个 `answer.delta` 后切换正文。
- 回答页由问题、回答、公开运行过程和证据区域共同组成。
- 低可信和证据不足回答不能与高可信回答使用完全相同的视觉状态。

### 9.3 知识空间

- 首屏展示空间名称、权限范围、索引健康度、文档数量、最近更新和失败任务。
- 上传页展示完整入库生命周期、解析结果、失败原因、重试和取消入口。
- 来源详情展示版本、上传人、更新时间、权限、切片和索引状态。

### 9.4 引用与原文

- 回答关键结论可以绑定 citation。
- citation 与右侧来源双向高亮。
- 打开原文时定位到对应页码、章节或段落，并展示相邻上下文。
- 返回回答后保留会话、滚动位置和选中 citation。

### 9.5 管理设置

- 访问与成员、激活密钥、索引策略和审计日志分区展示。
- 创建密钥时明文只展示一次。
- 撤销、重建索引等高风险操作需要二次确认和明确结果反馈。

## 10. 核心数据追溯链

第一版至少保证以下链路可追溯：

```text
tenant/user/access_key
  -> conversation/message
  -> answer_run/answer_run_event
  -> retrieval_run
  -> citation
  -> chunk
  -> document version
  -> source/knowledge space
  -> feedback/audit log
```

删除或被新版本替代的来源不得再进入新检索；已经生成的历史回答仍必须能定位到当时使用的
文档版本，且只允许具备审计权限的人员查看。

## 11. 通用完成定义

一个任务只有同时满足以下条件才可以标记完成：

- 功能行为与本文件、系统设计和前端设计一致。
- 正常、空状态、失败、超时、权限不足和重复操作有明确结果。
- 新增或修改的合同有自动化测试。
- 涉及前端时完成桌面端和窄屏浏览器回归，无控制台错误和横向溢出。
